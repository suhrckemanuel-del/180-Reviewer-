# Improvement log

Append-only. One entry every time the reviewer is used on real work and something was wrong.

**This is the whole improvement process.** A change to the prompt references the entry that
prompted it. No entry, no change — the project has already proved it can generate decisions
indefinitely without touching anything a user would notice.

Keep entries short. A line is enough. The point is that a real use, by a real person, on a real
deliverable, is what moves the tool.

## Format

```
## YYYY-MM-DD — who, what deliverable, release key
- What was wrong. Be specific enough that someone else could find it.
- What changed in response, or "nothing yet".
```

Anything that was right and useful is worth logging too. A device nobody has ever complained about
is a device nobody has tested.
