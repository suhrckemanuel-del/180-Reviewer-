# The decision-case framework

**Four questions, in order.** The standard structure for a should-we-do-X case.

Source: 180 Degrees Consulting Delft-Rotterdam case workshop,
`Warmtewerk-Framework-Slide-v2.pptx`. Drawn from Case in Point, IGotAnOffer and PrepLounge; format
style adapted from strategyu.co. Transcribed to markdown 2026-09-25 so the reviewer can reach it —
it previously existed only inside a PowerPoint and was invisible to every tool in this repo.

---

## WHAT SHOULD WE RECOMMEND?

### 1. MEASURE

- Which number decides it?
- Over what time horizon?
- What will we not trade away?

### 2. COST

- Cost per result: our money
- Cost per result: everyone's money
- Net of what happens anyway

### 3. COVERAGE

- Who does each option reach?
- Who does it leave out?
- How many? Multiply it out.

### 4. RECOMMENDATION

- What to do, and starting when
- What it costs us to do it
- What proves us wrong in a year

### Then, decide

Option A · Option B · Option C · Combine, or something new

> **You will not find the right answer. You will pick one, and be able to say why.**

## The framework in practice

**NightOwl Gym: which location?** One new site to open. Downtown: high rent, faster signups.
Suburb: low rent, higher retention.

**Which location should we open?**

| | |
|---|---|
| **MEASURE** | Year-1 signups, or year-3 members still training? *Downtown wins on signups only.* |
| **COST** | Cost per member still training at year 3. *Downtown: about €1,800. Suburb: about €654.* |
| **COVERAGE** | Downtown prices out local families once rent is covered. *Suburb has no downtown, lunch-hour traffic.* |
| **RECOMMENDATION** | Suburb, starting with pre-sold founding memberships. Gives up downtown professionals and faster year-1 cash. **Wrong if 12-month retention falls below 55%.** |

**Then, decide:** Downtown · Suburb · Wait and test · Franchise partner

*Same four questions. A different case.*

## Notes for wiring this into the reviewer

Not yet built. Recorded here so the next session starts from the framework rather than from a
description of it.

**What makes this one worth using first.** It is the chapter's own, already taught to its members,
and it is **decision-shaped** — which matches what the reviewer actually reviews. A 180DC
deliverable usually answers a client's should-we question, and this framework is a structure for
exactly that. Its closing line is also the project's stated goal, written independently: pick one,
and be able to say why.

**Where it should land in the output.** In a *"how would you apply this?"* field — the reviewer
names the framework and asks the consultant to work out the application, rather than applying it
for them. Decided 2026-09-24; see
[../decisions/REALIGNMENT-2026-09-24.md](../decisions/REALIGNMENT-2026-09-24.md), decision 6.

**The honest limitation, which has to be handled before it ships.** This is a framework for
decision cases. A deliverable that is not a should-we-do-X — market research, a process design, a
communications plan — gives the reviewer nothing to apply, and the feature goes quiet exactly the
way the worked example did. `01-rubric-v1.md` section C already carries an artifact-type scope
matrix that could decide when the framework is in scope. That matrix does not currently ship
either.

**The RECOMMENDATION bucket's third line is the sharpest thing on the slide.** *"What proves us
wrong in a year"* is a falsification test, and almost no student deck contains one. That single
question may be worth more to the reviewer than the other eleven combined.

**Source discipline.** If this becomes something the reviewer asserts, it needs an entry in
[../tools/quality-reviewer/v2/10-source-register.md](../tools/quality-reviewer/v2/10-source-register.md)
with its claim, its limitation and the dimensions it grounds — like every other claim the tool
makes. Case-interview prep material is a weaker source than the peer-reviewed entries already
registered, and that should be written down rather than glossed.
