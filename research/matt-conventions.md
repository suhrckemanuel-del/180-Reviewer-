# Which `mattpocock/skills` conventions earn a place at 180DC's size

Research for ticket [#10](https://github.com/suhrckemanuel-del/180-Reviewer-/issues/10), map [#7](https://github.com/suhrckemanuel-del/180-Reviewer-/issues/7). Written 2026-10-13. A research note: true on the day it was written, so check the sources before relying on it later.

**Sources.** The local plugin copy at `~/.claude/plugins/marketplaces/mattpocock`, which is commit [`3cca18b`](https://github.com/mattpocock/skills/tree/3cca18b368ae95cdbdebbff572ccafa662551015) (2026-09-04). Upstream `main` was [`49dd158`](https://github.com/mattpocock/skills/tree/49dd158d1076134a641b33efb035946536778336) (2026-10-09), 86 commits ahead; where upstream differs it is said. Links below written `M/<path>` mean `https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/<path>`; `U/<path>` means the same at `49dd158`. Platform facts come from Anthropic's own docs, linked inline.

**The 180DC situation the verdicts are judged against** (from map #7): one real skill (the deliverable reviewer, lead and student modes) and three named empty slots (coach, visuals, research); maintained by students who fully turn over in about three years; most users on claude.ai free plans uploading a zip; some on ChatGPT or Gemini; built by 27 Oct 2026.

## Two platform facts that decide several rows

1. **claude.ai rejects Claude Code-only frontmatter.** For "claude.ai skill uploads, the Skills API, and packaging with `package_skill.py`" the allowed fields are `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`. Anything else fails: "packaging or upload fails with a hard error instead of ignoring the field". Source: [Claude Code docs, Skills, "Using skill frontmatter outside Claude Code"](https://code.claude.com/docs/en/skills). The [Agent Skills spec](https://agentskills.io/specification) lists the same six fields. `disable-model-invocation` is not among them.
2. **claude.ai caps the description at 200 characters** and wants the zip to contain the skill folder as its root; skills are available on Free and need code execution enabled. Source: [Claude Help Center, "How to create custom skills"](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills). (The open spec allows 1024; claude.ai is stricter.) For scale: 5 of Matt's 25 promoted skill descriptions exceed 200 characters (counted from the `SKILL.md` frontmatter at `3cca18b`; `code-review` is 421).

Nothing in Matt's repo targets ChatGPT or Gemini web. His non-Claude target is Codex and other coding agents via skills.sh ([M/README.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/README.md)). For a ChatGPT/Gemini user, only the `SKILL.md` body as plain text carries over (inference: those web apps do not read the Agent Skills format, and no source here says they do).

## The verdicts

| # | Convention | What it does | Maintenance cost | Serves zip upload? | Verdict |
|---|---|---|---|---|---|
| 1 | Bucket folders + README per bucket | `skills/{engineering,productivity,misc,in-progress,deprecated}/`, each with a README listing its skills; promoted vs non-promoted gates the plugin and docs | Every add/rename touches bucket README, top README, `plugin.json` | No (repo layout only) | **Adapt**: flat `skills/<name>/`, one README that lists the real skill and names the three slots |
| 2 | `.claude-plugin/plugin.json` + `marketplace.json` | Ships the promoted set as a Claude Code plugin; version must track `package.json` | Version sync script, `claude plugin validate --strict`, changesets | No, Claude Code only | **Skip**: almost nobody installs this way; revisit if leads move to Claude Code |
| 3 | `CLAUDE.md` with `AGENTS.md` beside it | Maintainer-agent rules: the invariants that keep READMEs, manifest, docs and router in step | Low, but only if someone reads it | No (repo-level, never in the zip) | **Keep**: one short invariants file is the cheapest handover there is |
| 4 | `CONTEXT.md` / `GLOSSARY.md` | Shared vocabulary: terms, words to avoid, resolved ambiguities | Low, edited when a term is disputed | Only if the terms are copied into the skill folder | **Adapt**: keep the repo glossary for maintainers; put the few terms the skill needs inside the skill |
| 5 | `.agents/adr/` | Short decision records with the why and the invariants they create | One file per hard decision | No | **Keep**: the turnover problem is exactly "why is it like this?" |
| 6 | `.agents/` writing rules (`install-block.md`, `invocation.md`, `writing-docs.md`) | One canonical install wording; the invocation model; the docs-page template | Each rule file must be kept true | Indirectly (install wording) | **Adapt**: keep one canonical "how to install the zip" block; drop the other two |
| 7 | `docs/<bucket>/<skill>.md`, four-section pages | Human page per promoted skill: What it does, When to reach for it, Common questions, It's working if (published to aihero.dev) | Re-sync on every behaviour change; question hunt over issues and changelog | Yes, as the page a user reads before uploading | **Adapt**: one page for the reviewer, same four sections; no page for empty slots |
| 8 | User- vs model-invoked skills | `disable-model-invocation: true` (Claude Code) + `policy.allow_implicit_invocation: false` (Codex) so only a human can fire a skill | Two flags kept in sync per skill | **No: the field fails claude.ai upload** | **Skip** the flag; keep the idea only as description wording |
| 9 | `agents/openai.yaml` per skill | Codex picker metadata and the Codex half of the invocation flag | One file per skill, kept in sync with frontmatter | No, Codex only | **Skip**: no 180DC user is on Codex |
| 10 | `ask-matt` router | A user-invoked skill mapping every user-reachable skill and the flows between them | Must be re-read on every skill change, or it is "a router that lies" | No as written (it sets `disable-model-invocation`) | **Skip** until at least two slots hold real skills |
| 11 | `scripts/link-skills.sh` | Symlinks every non-misc, non-deprecated skill into `~/.claude/skills` and `~/.agents/skills` | Dev-only; re-run after add/rename | No | **Skip**: the 180DC equivalent is a script that builds the upload zip |
| 12 | `.out-of-scope/` (+ upstream `SCOPE.md`) | One file per rejected idea, with why and the prior requests; `SCOPE.md` sets the bar (an observed failure, fits the philosophy) | Near zero: write once when you say no | No | **Keep**: the cheapest guard against a successor re-adding a rejected feature |
| 13 | Changesets, `CHANGELOG.md`, release workflow, version sync | npm changesets generate the changelog and bump `plugin.json` on merge | Node toolchain, a CI workflow, a changeset per PR | No | **Skip**: the reviewer already has a version stamp and `IMPROVEMENT-LOG.md` |
| 14 | Skill-to-skill calls via "call the Skill tool", hard vs soft setup dependencies (ADR 0001) | How one skill invokes another; when a skill must point to a setup skill | Only matters with several interlinked skills | Unverified on claude.ai | **Skip** for now; one skill calls nothing |
| 15 | No em-dashes in prose | House style rule, rewrite not substitute | A rule to remember | Neutral | **Skip**: taste, not structure |

## Notes per row (evidence)

**1. Buckets.** Defined in [M/CLAUDE.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/CLAUDE.md): promoted skills "must have a reference in the top-level `README.md` and an entry in `.claude-plugin/plugin.json`'s `skills` array"; non-promoted ones "must not appear in either". The buckets exist to curate a subset of about 40 skills for the plugin ([ADR 0002](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/adr/0002-ship-as-a-claude-code-plugin.md)). With one real skill there is no subset to curate. The one idea worth borrowing is `in-progress/` as "public on purpose, feedback wanted" ([M/skills/in-progress/README.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/in-progress/README.md)), which maps onto the three slots. Recommendation, not a sourced fact: list the slots in the README rather than as folders holding a placeholder `SKILL.md`, since any `SKILL.md` someone zips becomes a live skill.

**2. Plugin manifests.** [M/.claude-plugin/plugin.json](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.claude-plugin/plugin.json) lists 25 skill paths; `version` must track `package.json` (ADR 0002, "Invariants this creates"), enforced by [M/scripts/sync-plugin-version.mjs](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/scripts/sync-plugin-version.mjs). [M/.agents/install-block.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/install-block.md): "The plugin is Claude Code only." Upstream has since changed the role of `marketplace.json` ("Every agent except Claude Code installs from it", [U/CLAUDE.md](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/CLAUDE.md)), which shows this layer still moves under him.

**3. CLAUDE.md / AGENTS.md.** At `3cca18b`, `AGENTS.md` is a git symlink (mode `120000`) to `CLAUDE.md`, added "so Codex reads the same repo instructions" ([M/CHANGELOG.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/CHANGELOG.md), 1.2.0). On this Windows machine the checkout materialised it as a 9-byte text file containing `CLAUDE.md`, not a link. If 180DC wants both names, make `AGENTS.md` a one-line pointer, not a symlink. These files reach a maintainer working in Claude Code or Codex, never a zip user.

**4. CONTEXT.md / GLOSSARY.md.** [M/CONTEXT.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/CONTEXT.md) holds terms, `_Avoid_` lists, relationships, flagged ambiguities. Upstream renamed it: `GLOSSARY.md` exists at `49dd158` with the same content and `CONTEXT.md` is gone ([U/GLOSSARY.md](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/GLOSSARY.md)). The reviewer repo already has a `CONTEXT.md`. A zip carries only the skill folder (help-center article above), so any term the skill must use has to live inside it.

**5. ADRs.** Two at `3cca18b` ([0001](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/adr/0001-explicit-setup-pointer-only-for-hard-dependencies.md), [0002](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/adr/0002-ship-as-a-claude-code-plugin.md)), each a page: context, decision, invariants, a dated update. Two ADRs in a 40-skill repo is the right density. The reviewer repo's `decisions/` already plays this role.

**6. Writing rules.** `install-block.md` exists because install wording drifted: docs pages "used to carry their own copy of these commands; those blocks are now deleted rather than corrected". `invocation.md` only matters with the flags in row 8. `writing-docs.md` is long and tied to aihero.dev (absolute links, AI Coding Dictionary links, a private wiki path) ([M/.agents/writing-docs.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/writing-docs.md)); borrow its four sections, not the file.

**7. Docs pages.** Template and bars in `writing-docs.md`: lead with the "defining constraint"; Common questions must be observed, not invented ("the count stays honest to the evidence"); each "It's working if" bullet must be checkable "without opening `SKILL.md`". Example: [M/docs/engineering/research.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/docs/engineering/research.md). These two bars match the 180DC rule of no invented content and suit a reader who is a lead or student deciding whether to upload. Cost is real: CLAUDE.md requires a re-sync on every behaviour change.

**8. User- vs model-invoked.** [M/.agents/invocation.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.agents/invocation.md). 22 `SKILL.md` files at `3cca18b` set `disable-model-invocation: true`. That field is outside the six claude.ai allows, so copying Matt's layout verbatim breaks the main install path (platform fact 1). Matt's own description rule still transfers: a model-reachable skill keeps "rich trigger phrasing", within claude.ai's 200 characters.

**9. `agents/openai.yaml`.** Example: [M/skills/engineering/ask-matt/agents/openai.yaml](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/ask-matt/agents/openai.yaml) (`display_name`, `short_description`, `policy.allow_implicit_invocation: false`). "Codex UI metadata" (`invocation.md`). It also shows the sync cost: 1.2.2 had to remove a wrong `policy` line that hid `writing-for-agents` from the Codex model, and fix a stale display name (CHANGELOG 1.2.2). Codex is not ChatGPT web.

**10. Router.** [M/skills/engineering/ask-matt/SKILL.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/skills/engineering/ask-matt/SKILL.md) routes about 25 skills along a main flow, on-ramps and standalones. CLAUDE.md makes keeping it accurate a standing duty. Upstream's [new-skills out-of-scope note](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/.out-of-scope/new-skills.md) names the router among the costs of every extra skill. With one skill there is nothing to route.

**11. link-skills.sh.** [M/scripts/link-skills.sh](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/scripts/link-skills.sh): "a dev-only script, intended for use by maintainers ... not a supported installer." It relies on `ln -s` (unreliable on Windows, see row 3) and on harness folders a claude.ai user doesn't have.

**12. Out-of-scope.** Three files at `3cca18b` ([M/.out-of-scope/](https://github.com/mattpocock/skills/tree/3cca18b368ae95cdbdebbff572ccafa662551015/.out-of-scope)), eight upstream, indexed by [U/SCOPE.md](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/SCOPE.md). Each is: the rejected concept, why, prior requests. `SCOPE.md`'s bar ("Observed failure. It describes something that went wrong in a real session ... A hypothetical improvement ... does not clear this part") matches the 180DC rule that real use beats internal measurement. This is the convention most directly aimed at a successor re-proposing something already rejected.

**13. Release machinery.** [M/package.json](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/package.json), [M/.changeset/config.json](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.changeset/config.json), [M/.github/workflows/release.yml](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/.github/workflows/release.yml). It exists to move the plugin version that Claude Code uses to decide on updates (ADR 0002). A zip has no update channel, so this buys nothing.

**14. Skill-to-skill calls.** `invocation.md`: dependencies are "an explicit instruction to call the Skill tool with the named skill". ADR 0001 splits hard and soft dependencies on a setup skill. I found no Anthropic source saying whether a claude.ai skill can invoke another this way, so this is unverified for the zip path and irrelevant while one skill exists.

**15. Em-dashes.** Last paragraph of [M/CLAUDE.md](https://github.com/mattpocock/skills/blob/3cca18b368ae95cdbdebbff572ccafa662551015/CLAUDE.md); upstream ran a repo-wide removal (changeset `remove-em-dashes-repo-wide.md`).

## What this adds up to for the build session

Keep four things: a short invariants file (row 3), ADRs (row 5, already `decisions/`), `.out-of-scope/` with a `SCOPE.md`-style bar (row 12), and a glossary (row 4). Adapt three: a flat skills folder with slots named in the README (1), one canonical zip-install block (6), one four-section page for the reviewer (7). Skip the rest; they serve Claude Code or Codex distribution, which 180DC's users don't use.

The hard constraint for whoever writes the `SKILL.md`: frontmatter limited to the six spec fields, description at most 200 characters, zip with the skill folder at its root.
