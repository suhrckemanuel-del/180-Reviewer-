# H-002 - Tools, optimization and consultant capability system

## For future Claude
Manuel's emerging 180DC model is not a collection of unrelated AI tools. Build one or two flagship workflows, improve them through measured evaluation loops, and teach consultants the underlying consulting and AI capabilities so the organization becomes stronger rather than dependent.

## The model

### Layer 1 - Consulting capability

Teach consultants how to:

- Frame the real decision and problem
- Structure analysis
- Research and evaluate evidence
- Synthesize governing insights
- Create specific recommendations
- Communicate through strong deliverables
- Use AI without outsourcing judgment

### Layer 2 - Shared AI working system

Provide:

- Approved tools and access
- Shared prompts, skills and examples
- Privacy and client-confidentiality rules
- Source-grounding and abstention requirements
- Human review and escalation
- Reusable branch knowledge

### Layer 3 - Flagship workflows

Prioritize a very small set:

1. **AI Quality Reviewer** - feedback and coaching for deliverables.
2. **Second workflow** - select only after problem discovery and evidence; recruitment remains gated.

### Layer 4 - Continuous improvement

For each workflow:

1. Establish a baseline.
2. Create a human-labeled evaluation set.
3. Identify one failure or cost driver.
4. Propose bounded improvements.
5. Test offline or in a sandbox.
6. Review with the accountable human.
7. Pilot with explicit success and guardrail measures.
8. Adopt, revise or roll back.
9. Preserve the learning for future cycles.

## Why this is stronger than tools alone

- Workshops without workflow use may be forgotten.
- Tools without teaching can weaken judgment and create dependence.
- Optimization without evaluation can improve the wrong metric.
- A combined system lets workshops teach principles, tools reinforce them during work and evaluation data improve both.

## Workshop-to-workflow loop

`teach principle -> practice on realistic case -> use during project -> receive reviewer feedback -> reflect on mistakes -> update training and tool`

The reviewer therefore becomes both a quality-control system and a source of anonymized capability-gap evidence.

## Proposed sequence

1. Define the branch's consulting capability map.
2. Build the first workshop around deliverable quality and responsible AI use.
3. Run the AI Quality Reviewer golden-set and live-proof work.
4. Pilot the workshop and reviewer with the same cohort.
5. Compare baseline and post-intervention work.
6. Improve the workshop, rubric and reviewer from observed failure patterns.
7. Select the second workflow only after reviewing the wider 180DC problem portfolio.

## Workspace implementation

Treat the branch AI system as a structured workspace rather than one universal chat:

- Durable branch instructions and decision rights
- Consulting methods and project templates
- Approved source and research procedures
- Quality rubric and anonymized examples
- Reusable reviewer and project-setup skills
- Privacy and client-confidentiality rules
- Evaluation fixtures and improvement history
- Separate draft, reviewed and approved outputs

The first complete vertical slice should connect the workshop and reviewer:

`draft deliverable -> rubric-grounded review -> cited findings -> consultant revision -> team-lead confirmation -> anonymized lesson added to training`

This makes the tool an implementation layer for consultant development rather than a substitute for it.

## Guardrails

- No client-confidential material in unapproved systems.
- No autonomous changes to live workflows.
- No optimization without a baseline and rollback.
- No tool success metric that ignores consultant learning.
- No workshop judged only by attendance or satisfaction.
- No claim of improved quality without human evaluation.

## Success evidence

- Consultants can explain and transfer the taught principles.
- Deliverables improve against a stable human rubric.
- Reviewer findings are supported, useful and calibrated.
- Project leads spend less time on repeated avoidable corrections.
- Consultants retain agency and improve over successive submissions.
- The system produces reusable institutional knowledge.
