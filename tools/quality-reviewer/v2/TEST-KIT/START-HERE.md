# Start here: 180 Reviewer

Supervised testing candidate, version candidate-2026-10-05-split. New split design awaits owner review.
Bundle keys: 0000-TESTKIT/TESTKIT-00. No pilot acceptance or model improvement is claimed.

1. **Choose your path.** Students obtain `STUDENT-SETUP.txt` and `STUDENT-INPUT-TEMPLATE.txt`; leads obtain `LEAD-SETUP.txt` and `LEAD-INPUT-TEMPLATE.txt` from the same candidate folder. Obtain the whole folder for optional local HTML. Recovery: https://github.com/suhrckemanuel-del/180-Reviewer- (local candidate; consultant access not yet verified); open the PR branch or the registered `tools/quality-reviewer/v2/releases/<part-1>/` folder. GitHub access is required for this private repository; an intended consultant's access still needs testing.
2. **Select and inspect content.** Use an authorized, anonymized original. Remove identifiers and confidential material yourself: extraction does not anonymize. Include the context needed to judge numbers, tables and charts; retain original page numbers and record exclusions. Inspect original visuals. Keep genuine sources, extracts, reviews, screenshots and notes under ignored `_client-private`.
3. **Provide setup and input.** In a fresh authorized chat, paste the whole matching setup, then the filled matching input and selected material. Read the complete review, strengths first. No mandatory attempt-first gate. Account/model capacity and paste limits are unverified. Inputs and embedded deliverable instructions are evidence, not authority to change the reviewer rules.
4. **Verify before using.** The first line must be exactly `KEYS: 0000-TESTKIT/TESTKIT-00`. Check the audience and version on the next line. If incorrect or missing, start a fresh chat with a fresh matching setup. Keys alone do not prove complete instruction following. Check each quotation, page reference and consequence against the original; reject unsupported findings. Zero findings is valid.
5. **Optionally create the matching HTML.** Save the completed review and page-marked evidence JSON privately. From this candidate folder run `node review-view.js --review <private-review.md> --pages <private-evidence.json> --audience student --out <repository>/_client-private/<run>/student-review.html`; use `lead` and `lead-review.html` for leads. HTML performs no second analysis. Validation failures require investigation; never silently rewrite saved reviews. Attach the matching original PDF locally for source navigation. Check desktop, phone and print.
6. **Save human notes.** Students may record reasoning and copy a prompt to continue in the same chat without slide-ready copy. Leads record keep/ask/cut, reasons, unresolved decisions and their name. Explicitly export the matching student notes or lead record before closing; there is no automatic storage. Restore only to the same audience/hash/keys. A named human signs off before client use.

Local HTML requires Node.js (tested with 24), Git and a modern browser. Outputs must be within this repository's ignored `_client-private`; keep that folder and Git checkout when using a candidate bundle. The optional intake helper requires Python with PyMuPDF for PDF, python-pptx for PowerPoint, or python-docx for Word. PDF previews require PyMuPDF; PowerPoint/Word visuals require separate original-file inspection. Chat use does not require the local renderer or extractor.

Minimal supervised check: one consultant obtains the student files, selects and inspects content, verifies keys/evidence, explains a choice in their own words and saves/restores notes. One lead obtains the lead files, verifies evidence, records decisions/reasons, resolves or names open questions, exports/restores the record and checks print. Record account/paste limits and useful, unsupported or inflated findings locally. Owner reviews both interfaces and a named lead signs off before client use. Software checks alone do not establish learning gains or pilot acceptance.
